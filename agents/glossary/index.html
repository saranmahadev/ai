Agents Glossary

164 terms from Agents.

Action guardrail
a check that matches a proposed action's structured parameters against a policy before it executes. from Guardrails for Agent Actions
Agent
a system that decides its own next step at run-time, flexible but less predictable. from Agents vs. Assistants vs. Workflows
Agent benchmark
a task suite that drops an agent into a live environment with a goal, rather than checking one generated output against one reference. from Agent Benchmarks and Task Suites
Agent-time retrieval
running a retrieval step continuously during an agent's task, rather than once per external question. from Memory Retrieval as Agent-Time RAG
Amortized planning cost
a plan's one-time cost spread across however many cheap execution steps it stays valid for. from When Planning Hurts More Than It Helps
Assembly step
combining the separate worker calls' outputs into one coherent final result. from Orchestrator-Workers
Assistant
a single-turn or simply-turn-taking conversational system with no autonomous multi-step drive. from Agents vs. Assistants vs. Workflows
Attacker-achievable actions
the actions an attempted manipulation can actually carry out, limited by which tools were granted. from Excessive Agency and Scope Limits
Augmented LLM
a model call combined with tools, memory and retrieval as its three standard additions. from The Augmented LLM
Blast radius
how much damage a mistake or attack can cause, bounded by what it can actually reach. from Sandboxing and Isolation
Blind spot (in evaluation)
information a single summary metric discards, here the distance between a failing run and success. from Success-Rate Metrics and Their Blind Spots
Branching factor
the number of choices a planner has to weigh at a single decision point. from Hierarchical Task Planning
Call budget
the number of LLM calls an approach needs for a given number of steps. from Plan-and-Execute Agents
Call count
the number of model-to-tool round trips a given approach requires for a task. from Code as a Tool-Calling Interface
Challenger
the agent whose role is to independently check or dispute the proposer's claim. from Debate and Adversarial Multi-Agent Setups
Circular wait (deadlock)
a cycle of agents each blocked on a result only another in the cycle can produce, so none can proceed. from Coordination Failures and Deadlock
Classification step
the part of routing that determines which category a request belongs to. from Routing Between Specialized Prompts
Click error
the distance between a predicted click location and the target's true center. from Computer-Use Agents and GUI Grounding
Closed-loop execution
checking each action's real outcome before deciding the next step. from Open-Loop vs. Closed-Loop Behavior
Coarse action space
a generic action with no parameter to specify a target, unable to express which one is meant. from Action-Space Design and Its Failure Modes
Code as a tool-calling interface
letting a model express an action (including loops and conditionals) as generated code executed in a sandbox, rather than as one discrete structured call per action. from Code as a Tool-Calling Interface
Compounding cost
a loop's total cost growing faster than linearly because each iteration's own cost is higher than the last. from Cost and Latency of Agent Loops
Compression ratio
the raw store size divided by the fixed summarized size. from Memory Compression and Forgetting
Controller
the component that checks a step's result against the goal and decides whether to loop again. from Anatomy of an Agent Architecture
Cost per success
total cost per attempt divided by success rate — the cost of achieving one successful run, accounting for failed attempts. from Cost and Reliability as Joint Metrics
Crossover point
the volatility at which planning and reactive execution cost the same total time. from When Planning Hurts More Than It Helps
Cumulative success probability
the chance that at least one of n independent tries succeeds. from Handling Tool Errors and Retries
Data dependency
one tool call needing another call's result as an input. from Parallel vs. Sequential Tool Calls
Debate
a multi-agent setup where opposing roles argue a question before a judgment is reached. from Debate and Adversarial Multi-Agent Setups
Dependency violation
a subtask appearing in an order before one of its own prerequisites has completed. from Goal Decomposition into Subtasks
Dependency-respecting order
a sequence of subtasks where every task runs only after everything it depends on has already completed. from Capstone: A Goal, Decomposed, Executed and Verified End to End
Dependent chain
a sequence of tool calls where each one needs the previous one's result, forcing sequential execution. from Parallel vs. Sequential Tool Calls
Detection point
the moment a failure is actually noticed, which determines how much wasted effort happens before recovery begins. from Re-Planning on Failure
Diminishing returns (in voting)
each additional sample improving accuracy by a progressively smaller amount. from Parallelization: Sectioning and Voting
Duplicated work
independent agents each redoing a subtask that only needed to be completed once. from Coordination Failures and Deadlock
Dynamic decomposition
figuring out what a task's pieces are at run time, rather than fixing them in advance. from Orchestrator-Workers
End-to-end trace
following one goal through every stage of a pipeline in order, rather than examining each stage in isolation. from Capstone: A Goal, Decomposed, Executed and Verified End to End
Enumerated action space
one distinct action per candidate target, whose size grows with the number of candidates. from Action-Space Design and Its Failure Modes
Episode
a record of a specific task attempt, the approach tried, and its outcome. from Episodic Memory and Experience Logs
Episodic memory
a long-term memory store specifically of an agent's own past episodes. from Episodic Memory and Experience Logs
Error attribution
identifying which specific step in a trajectory actually caused an observed failure. from Error Attribution Across a Trajectory
Error propagation
a mistake at one step silently feeding into and corrupting every step that depends on it. from Self-Critique Loops in Agents
Evaluator
the role that judges a candidate and returns specific, actionable feedback. from Evaluator-Optimizer Loops
Evaluator-optimizer loop
a workflow pairing a generating/revising call with an evaluating call that gives feedback, repeated until a stopping condition. from Evaluator-Optimizer Loops
Excessive agency
granting an agent tools, permissions, or autonomy beyond what its task requires. from Excessive Agency and Scope Limits
Failure propagation
later steps failing because they depended on an earlier step's result that never actually materialized. from Re-Planning on Failure
Feedback carried forward
appending the result or correction from one attempt into the prompt for the next. from Learning from Feedback Without Weight Updates
Flat cost estimate
the (inaccurate) assumption that every iteration of a loop costs the same as the first one. from Cost and Latency of Agent Loops
Forgetting (deliberate)
discarding detail on purpose, as the cost of keeping the overall store at a usable, bounded size. from Memory Compression and Forgetting
Free-text field
a parameter that accepts any string, leaving format ambiguity undetected until the tool tries to use the value. from Designing Tools for Agent Reliability
Full mesh
a topology where every pair of agents has a direct link. from Swarm and Peer-to-Peer Coordination
Generalist agent
an agent built to be adequate across many skills rather than excellent at one. from Role Specialization in Agent Teams
Goal decomposition
breaking a goal into subtasks and the dependencies between them. from Goal Decomposition into Subtasks
Grounding
mapping a described or inferred target onto an actual pixel coordinate to act on. from Computer-Use Agents and GUI Grounding
Growing transcript
the accumulated history an agent's reasoning call includes with every new iteration. from Cost and Latency of Agent Loops
Handoff
the point where one stage's output becomes the next stage's input. from Pipeline and Sequential Handoff
Heavy retries
a configuration that re-attempts a task multiple times to raise its success rate, at a proportional cost. from Cost and Reliability as Joint Metrics
Hierarchical task network (HTN)
a planning approach that decomposes a goal into tasks, then those tasks into sub-tasks, continuing down to primitive actions. from Hierarchical Task Planning
High-risk pattern
a rule identifying action parameters (a command, a table, an amount) that should be blocked or flagged. from Guardrails for Agent Actions
Hijacked action
a real action an agent takes as a result of following an injected instruction rather than its actual task. from Prompt Injection in Agent Contexts
Hit test
checking whether a predicted click falls within a target's bounding box. from Computer-Use Agents and GUI Grounding
Human-in-the-loop
every action requires a person's approval before it runs. from Autonomy Levels and Human Oversight Tiers
Human-on-the-loop
the agent runs autonomously, but irreversible actions are routed through a person first. from Autonomy Levels and Human Oversight Tiers
Human-out-of-the-loop
the agent acts fully autonomously, with no approval step at all. from Autonomy Levels and Human Oversight Tiers
Hybrid action space
an action space combining code execution and direct GUI interaction, chosen per step. from Hybrid Code-and-GUI Action Spaces
In-context learning
a model's behavior changing based on what's included in its current context, with no weight updates involved. from Learning from Feedback Without Weight Updates
Independent calls
tool calls with no data dependency between them, which can run in parallel. from Parallel vs. Sequential Tool Calls
Index-based targeting
referring to an element by its position in an observed list or DOM order. from Web-Browsing Agents
Inline correction
fixing a detected mistake immediately, before it can affect later steps. from Self-Critique Loops in Agents
Interleaved (ReAct-style)
an agent pattern that reasons about what to do at every step, rather than committing to a plan in advance. from Plan-and-Execute Agents
Isolation
containing a process so its effects can't spread beyond an intended boundary. from Sandboxing and Isolation
Joint metric
a single number (like cost per success) that combines two individually incomplete metrics into one that reflects the actual trade-off. from Cost and Reliability as Joint Metrics
Least-privilege scope
granting only the tools a task genuinely needs, nothing more. from Excessive Agency and Scope Limits
Linear forward scan
checking a trajectory's steps in order until the broken one is found. from Error Attribution Across a Trajectory
LLM-as-judge (for trajectories)
using a model to read and score an agent's full run, applying the same judging mechanism used for single outputs. from LLM-as-Judge for Agent Trajectories
Localized failure
a problem caught and fixed at the specific action that caused it, rather than requiring the whole trajectory to be redone. from Verifier-Guided Agent Loops
Long-term memory
anything deliberately written to external storage that a later, separate run can read back. from Short-Term vs. Long-Term Agent Memory
Loop
repeatedly feeding a result back in and calling again until a goal is met or a budget runs out. from From a Single Call to a Loop
Memory (in this context)
state that persists across turns or runs, as opposed to what's baked into the model's weights. from The Augmented LLM
Memory compression
periodically folding older memory entries into a bounded summary. from Memory Compression and Forgetting
Memory store
the collection of an agent's embedded past facts and experiences that retrieval ranks against. from Memory Retrieval as Agent-Time RAG
Monotonic failure
a condition that, once false, stays false for every later step. from Error Attribution Across a Trajectory
Multi-hop goal
a goal that can't be reached in one step because each step's result is needed to determine the next step. from From a Single Call to a Loop
Observability
the ability to inspect what actually happened during a run after it finishes. from Observability and Tracing for Agent Runs
Open-loop execution
running a sequence of actions without checking their actual results. from Open-Loop vs. Closed-Loop Behavior
Optimizer
the role that generates or revises a candidate based on feedback. from Evaluator-Optimizer Loops
Orchestrator-workers
a pattern where an orchestrator call dynamically decides a task's subtasks, then dispatches one worker call per subtask and assembles the results. from Orchestrator-Workers
Outcome-only verdict
a pass/fail judgment based solely on the final result, blind to how it was reached. from Trajectory-Level Evaluation
Oversight tier
which category of an agent's actions require a human's approval before running, scoped specifically to irreversible or high-risk ones. from Capstone: A Goal, Decomposed, Executed and Verified End to End
Parameterized action space
one action type that takes a target as an argument, keeping the space's size constant regardless of candidate count. from Action-Space Design and Its Failure Modes
Partial credit
a continuous measure, between 0 and 1, of how much progress a run made toward the goal. from Success-Rate Metrics and Their Blind Spots
Per-step strategy selection
choosing the action type for each individual step of a task, rather than committing to one action type for an entire task. from Hybrid Code-and-GUI Action Spaces
Perceive
the component that reads the current request and any new observations. from Anatomy of an Agent Architecture
Permanent error
a failure that will recur identically on every retry, because its cause doesn't change between tries. from Handling Tool Errors and Retries
Persist
to write a fact somewhere that outlives the current run. from Short-Term vs. Long-Term Agent Memory
Pipeline
a fixed sequence of specialist agents, each handing its output directly to the next. from Pipeline and Sequential Handoff
Plan-and-execute
an agent pattern that decomposes a goal into a full ordered plan once, then executes each step without further planning calls. from Plan-and-Execute Agents
Planner
the component that decomposes a goal into an ordered sequence of steps. from Anatomy of an Agent Architecture
Position bias
a judge's tendency to favor whichever item is shown first, independent of actual quality — unchanged when judging trajectories instead of single outputs. from LLM-as-Judge for Agent Trajectories
Primitive action
a task simple enough to just be executed, with no further decomposition. from Hierarchical Task Planning
Production agent loop
the repeating observe-reason-act-verify cycle a running agent executes each iteration. from Production Agent Architecture
Prompt chaining
a fixed sequence of LLM calls, each one's output feeding into the next. from Prompt Chaining
Prompt injection
text crafted to look like an instruction, embedded in content a model reads, attempting to redirect its behavior. from Prompt Injection in Agent Contexts
Proposer
the agent that generates an initial claim or answer. from Debate and Adversarial Multi-Agent Setups
Re-planning
detecting that a plan's step failed and generating a new plan for the remaining steps instead of continuing the original one. from Re-Planning on Failure
Reason stage
the LLM call deciding what to do next, typically the loop's dominant latency cost. from Production Agent Architecture
Recall@K
whether the correct item survives being limited to the top K candidates. from Tool Selection Among Many Candidates
Rediscovery cost
the attempts spent finding a working approach from scratch, paid again by every instance that lacks access to a log of what already worked. from Episodic Memory and Experience Logs
Redundant fetch
re-retrieving a value another step already obtained, when nothing about that value has changed. from Shared State Across a Multi-Step Task
Result verification
checking that a tool call's returned result actually has the content the next step needs, beyond just confirming the call didn't raise an error. from Tool Result Verification
Retry budget
the maximum number of retries allowed per action before the loop gives up or escalates. from Verifier-Guided Agent Loops
Role specialization
assigning each required skill in a team to an agent built and tuned specifically for it. from Role Specialization in Agent Teams
Routing
classifying an incoming request and dispatching it to a specialized prompt built for that category. from Routing Between Specialized Prompts
Sandbox
an isolated execution environment that restricts what a running process can reach. from Sandboxing and Isolation
Scope gate
restricting which actions are available at all, so an injected instruction has nothing exploitable to request. from Prompt Injection in Agent Contexts
Sectioning
splitting a task into independent subtasks run in parallel, finishing in the time of the slowest piece. from Parallelization: Sectioning and Voting
Selector-based targeting
referring to an element by a stable identity — a role, id, or visible text — that survives changes elsewhere on the page. from Web-Browsing Agents
Self-critique loop
an agent checking its own last output against what it should have produced, before proceeding. from Self-Critique Loops in Agents
Shared awareness
knowledge, available to every relevant agent, of what's already been claimed, completed, or is being waited on. from Coordination Failures and Deadlock
Shared state (blackboard)
a store any step of a task can write to and any other step can read from, scoped to that one task's run. from Shared State Across a Multi-Step Task
Short-term memory
the current run's working context, gone once the run ends. from Short-Term vs. Long-Term Agent Memory
Silent failure
an action that fails without raising any error, detectable only by checking its actual effect. from Open-Loop vs. Closed-Loop Behavior
a tool call that reports success while returning an incomplete or empty result. from Tool Result Verification
Silent validation failure
a code-based action that completes without error but skips interface logic (like form validation) tied to real user-input events. from Hybrid Code-and-GUI Action Spaces
Sim-to-real gap
the mismatch between a simulation's dynamics and the real environment's, which can make simulated training results not transfer. from Simulated and Game Environments
Simulated environment
a model of an environment an agent can act in and reset cheaply, standing in for a real one during training or testing. from Simulated and Game Environments
Single call
one request to a model, producing one result, with no further iteration. from From a Single Call to a Loop
Single point of failure
a component whose failure disconnects every participant that depended solely on it. from Supervisor-Orchestrator Patterns
a component whose failure disconnects every participant that depended solely on it — present in a star, absent in a mesh. from Swarm and Peer-to-Peer Coordination
Span
one recorded unit of a trace — typically one step's full record. from Observability and Tracing for Agent Runs
Specialist prompt
a prompt built and tuned for one specific category of request. from Routing Between Specialized Prompts
Stage breakdown
how a loop iteration's total latency divides among its constituent stages. from Production Agent Architecture
Staleness
a cached shared value no longer matching the current true value, because something changed after it was written. from Shared State Across a Multi-Step Task
a plan or observation no longer matching the actual state of the world by the time an action executes. from Web-Browsing Agents
Star (hub-and-spoke) topology
a communication structure where every participant links only to a central hub, never to each other. from Supervisor-Orchestrator Patterns
State-check grading
verifying success by inspecting the environment's resulting state rather than matching generated text. from Agent Benchmarks and Task Suites
Stateful (persistent) execution
a code environment whose variables and setup persist across separate calls. from Code-Execution Agents
Stateless execution
a code environment that starts fresh each call, with nothing carried over from before. from Code-Execution Agents
Strict schema
a parameter definition that only accepts a defined format, rejecting anything else before the tool's own logic runs. from Designing Tools for Agent Reliability
Structured function calling
a schema-checked tool call representing exactly one discrete action. from Code as a Tool-Calling Interface
Structured parameters
the specific, checkable fields of a proposed action, as opposed to unstructured free text. from Guardrails for Agent Actions
Success rate
the fraction of runs that cross the pass/fail threshold, with no information about how close the rest came. from Success-Rate Metrics and Their Blind Spots
Supervisor (orchestrator)
the single agent that routes subtasks to specialists and collects their results, with no direct specialist-to-specialist communication. from Supervisor-Orchestrator Patterns
Swarm (peer-to-peer)
a multi-agent system where agents coordinate directly through shared state, with no central router. from Swarm and Peer-to-Peer Coordination
Task suite
a curated collection of benchmark tasks, often spanning several environments (browsing, coding, tool use). from Agent Benchmarks and Task Suites
Tool
a function an agent can call to take an action or fetch information beyond its own training. from The Augmented LLM
Tool interface design
the choices (parameter types, validation strictness, error behavior) that shape how a tool can be called. from Designing Tools for Agent Reliability
Tool retrieval
ranking available tools by relevance to a task and keeping only the top K as candidates for selection. from Tool Selection Among Many Candidates
Top-K
the number of highest-similarity memories actually pulled back for use. from Memory Retrieval as Agent-Time RAG
Topological order
an ordering of a dependency graph's tasks that places every task after all of its prerequisites. from Goal Decomposition into Subtasks
Tracing
recording each step of a run as its own span, capturing its tool, input, output, latency and cost. from Observability and Tracing for Agent Runs
Trajectory score
the fraction of a run's steps judged valid, independent of whether the final outcome was correct. from Trajectory-Level Evaluation
Trajectory transcript
the full record of an agent's steps, typically far longer than a single generated response. from LLM-as-Judge for Agent Trajectories
Trajectory-level evaluation
checking every step of an agent's run, not just its final answer or state. from Trajectory-Level Evaluation
Transient error
a failure with some real chance of not recurring if the same call is tried again. from Handling Tool Errors and Retries
Trial-and-error learning
improving a policy by acting, observing the outcome, and adjusting — which necessarily includes early, bad attempts. from Simulated and Game Environments
Triangular growth
a quantity that grows as 1+2+3+...+n, compounding faster than a fixed multiple of n. from Code-Execution Agents
Validation gate
a check between chained steps that verifies an intermediate result before letting it proceed. from Prompt Chaining
a check applied to an intermediate result before letting it proceed to the next step. from Tool Result Verification
Validation gate (agent-level)
a check at a handoff that verifies a stage's output before the next stage runs on it. from Pipeline and Sequential Handoff
Verifier-guided loop
an agent loop where a separate verifier checks and retries each action immediately, rather than only checking the final result. from Verifier-Guided Agent Loops
Volatility
how often the environment changes, measured here as steps between changes (lower volatility means more frequent change). from When Planning Hurts More Than It Helps
Voting
running the same prompt multiple times and taking the most common answer. from Parallelization: Sectioning and Voting
Weight update
a change to a model's trained parameters — explicitly absent from everything in this topic. from Learning from Feedback Without Weight Updates
Weighted team accuracy
the overall accuracy across required skills, each scored at whichever agent actually handles it. from Role Specialization in Agent Teams
Workflow
a fixed, developer-coded sequence of calls, predictable but inflexible. from Agents vs. Assistants vs. Workflows
Workflow pattern
a structured, developer-controlled arrangement of calls, as opposed to an autonomous agent's self-directed loop. from Prompt Chaining
Worst-case accuracy
the success rate of a selection that has no signal beyond the candidate set itself. from Tool Selection Among Many Candidates
