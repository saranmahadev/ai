LLMs in Practice

LLMs1 min read

The last part of this subject: adapting a model to a specific task, prompting and serving it as part of a real product, the practical failure modes of each, and a capstone that traces the whole subject from raw pretraining to an aligned, usable assistant.

Topics in this section:

  • Fine-Tuning for a Specific Task: adapting a pretrained, aligned model to one narrow job.
  • Catastrophic Forgetting in Fine-Tuning: when teaching a model something new makes it worse at what it already knew.
  • System Prompts and Prompt Templates: the hidden instructions that shape every response before a user's own words arrive.
  • Structured Output and Tool-Calling APIs: getting a model's output into a shape your code can rely on.
  • Model Merging and Weight Averaging: combining several fine-tuned models into one, without training a new one from scratch.
  • Cost and Latency of LLM APIs: what actually determines how much a request costs and how long it takes.
  • Choosing a Model for a Task: matching a model's size, cost and capabilities to what a task actually needs.
  • Guardrails and Deployment-Time Safety Filters: the checks that run around a model in production, not inside it.
  • Capstone: Pretraining to Aligned Assistant, Traced End to End: following one model through every stage this subject covered, in order.

Fine-Tuning for a Specific Task

An aligned, general-purpose assistant is often not what a product actually needs — a narrower model trained specifically on one job's data can do that one job better, cheaper, and more predictably.

Catastrophic Forgetting in Fine-Tuning

Fine-tuning a model to be excellent at one narrow task can quietly make it worse at everything it used to do.

Structured Output and Tool-Calling APIs

Code that calls an LLM usually needs the response in a specific shape — valid JSON with particular fields, or a specific function call with typed arguments — not free-flowing prose.

Model Merging and Weight Averaging

Training a brand-new model that's good at two different tasks usually means training on both tasks' data together.
